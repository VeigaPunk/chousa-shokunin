# Round 26 sourced-claim critique

## Axes
- Freshness is primary; calibration/provenance is secondary. This finding does not change C1 operability.

## Counterexample and evidence
- The most defensible C2 sourceable clause is the meaning of calendar-day addition, not the result's truth: spec v1 says `V+N` days on the proleptic Gregorian calendar and `overdue` only when as-of is strictly after due (`corpus/evidence/round26-claims.md:65-73`). Python's official `datetime` reference says “Return the proleptic Gregorian ordinal of the date, where January 1 of year 1 has ordinal 1” (`https://docs.python.org/3/library/datetime.html`, `date.toordinal`, accessed 2026-10-21); its `date` arithmetic table says `date2` is `timedelta.days` after `date1` (`date` objects, arithmetic table). This supports only Python `date`/`timedelta` semantics for representing N Gregorian days after a date (and, if the oracle uses that API, its arithmetic semantics). It cannot establish that a record is fresh, that the lane ought to define `<N>d` from `verified-at`, or that the gate implements the rule correctly. It is Tier A only for Python API semantics; limit the row scope to that behavior/year range, and label adopting it as the lane's rule an inference.
- A cadence source could ground only a domain-bounded rationale such as periodic currency assessment. Existing S029 states that Cochrane reviews should be assessed periodically to decide whether an update is needed; it does not define an interval, `due=verified-at+N`, or a generic record policy (`corpus/SOURCES.md:39`; `corpus/knowledge/metadata-screen-r25.md:4,20-27,85-99`). S029 was opened in round 25, so merely re-citing it does not demonstrate a round-26 opening. Any new source must explicitly cover the population asserted; do not generalize systematic-review guidance to all knowledge entries.
- An event/update source is weaker for the `on-release` mapping. Crossref's Crossmark material is specifically about status/update metadata for participating scholarly content; it may support checking that scoped status, not that any source's release is a universal freshness trigger. The existing Crossmark row was opened in round 25 (`corpus/SOURCES.md:38`; `corpus/lessons/round-25.md:77`). `on-release => freshness=event` is presently a lane enum/design choice (`corpus/evidence/round26-claims.md:67-70`), not a sourced fact; cite an event source for it only if its stated scope actually covers the event and population.
- Strongest false-positive: a citation placed beside the whole C2 rule and described as validating freshness. QUALITY 7 requires a tier-A/B row whose scope covers the claim; a tier-C/community row cannot stand alone, and out-of-scope use must be labelled inference (`corpus/QUALITY.md:24-27`). QUALITY 8 separately forbids collapsing source-opens, relevance, support, and truth (`corpus/QUALITY.md:28-31`). Round 25 already corrected this exact overreach: S029's scheduled recheck is a lane inference, not Cochrane's requirement; PROV entity lifetime is not verification validity (`corpus/knowledge/metadata-screen-r25.md:87-99,121-125`).

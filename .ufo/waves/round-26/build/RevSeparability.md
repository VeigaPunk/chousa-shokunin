# Round 26 — separability and axis-harm review

## Finding — medium: separable claims, shared execution substrate
- Axes: C1 bounded-reader operability; C2 freshness classification; C3 registry-link calibration.
- Each can be tested with the other feature flags absent: the probe’s C1 path calls plain `verify-metadata`, C2 invokes only `--as-of`, and C3 invokes only `--registry` (`round26-measure.sh:51-84,86-172,174-223`). At base, C2/C3 are independently falsifiable as absent flags (before log: C2 0/29, 0/6; C3 0/5, 0/1).
- Not fully isolated in an integrated tree: all three execute `verify_metadata`; C1 changes its snapshot-to-lines loop (`tools/research-gate.sh:2351-2434`, especially 2383-2392), while C2/C3 consume that parser’s values. C3 additionally must read the registry through the same fd-bound/refusal path (`round26-claims.md:90-97`). Thus C2/C3’s meanings are independent of C1’s optimization, but their observed parsing/refusal/performance is not. Run each probe on a base-derived state with only its own change for attribution, then re-run holds on cumulative states.
- C2 and C3 are separate flags but share the global argument parser, output assembly, `N_DRIFT`/verdict path, and `verify_metadata`; simultaneous `--as-of --registry` behavior is not specified or measured. Define composition (both fields/findings, one verdict) and test it after isolated probes.

## Cross-axis harm exposure
- C1 → C2/C3 and legacy: a streaming rewrite can change line boundaries, CRLF/final unterminated-line handling, fenced-block and continuation parsing, or first-`## ` stop semantics, changing existing `source`/`verified-at`/`recheck` values, C2 dates, C3 IDs, output, drift/exit status. Changing the shared read path can also weaken denylist/stat/multilink/size/NUL/read refusals or fd-bound snapshot identity; those refusals are explicitly invariant (`round26-claims.md:34-37`; current refusal path `tools/research-gate.sh:2343-2387`). A slow per-line implementation can improve peak memory yet regress selftest/normal runtime; the probe records elapsed time but its prediction/threshold is only amplification/300-second timeout (`round26-claims.md:39-48`). Help is not meant to change, but a wider dispatch refactor can alter usage/error text.
- C2 → legacy/C3: un-gated due fields or overdue findings alter no-flag output, finding/drift counts, final verdict and exit code; date logic can misread shared header values that C1 changes, and can change C3’s combined output/status. New work on every default invocation can slow the existing 161-case suite. Refused entries must remain refused (spec says `due=refused freshness=refused`); missing/invalid `--as-of` must exit 2, and the flag must be rejected outside metadata mode. Usage must advertise the new form while retaining the old form checked by `metadata-usage` (`tools/research-gate.sh:306,5660-5666`).
- C3 → C1/C2/legacy: registry parsing can reintroduce line-proportional allocation or weaken the same size/denylist/multilink/NUL/read/fd checks; a capped 8 MiB registry can still amplify memory under the current per-line-array pattern. Findings leaking without `--registry` alter legacy output/exit; with it, false matches or wrong duplicate/header/used-by interpretation harm calibration and may change drift. Extra default-path work can slow selftests. Refused/unreadable/no-valid-table registry must exit 2 without weakening entry refusal. `--registry` must be metadata-only and appear in usage without removing the old usage substring.

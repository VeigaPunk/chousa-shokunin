## Reconstructed contract and divergence
- **What r24 meant by “overdue”:** only that a command by itself cannot make an overdue state computable. The last-known-good r24 behavior is structural schedule recognition / metadata admission, not a freshness verdict: an ISO date, cadence, or event token can pass the shape predicate without any due calculation. This matches the later base description at `corpus/evidence/round26-claims.md:54-57`.
- **Start date:** r24 did not specify whether an entry cadence starts at `verified-at` or `opened`. For entries, `verified-at` records a date and what was checked (`QUALITY.md:20-21`); `opened` belongs to a SOURCES registry row (`CORPUS.md:105-108`). Do not project the registry census’s `opened + Nd` onto entry freshness.
- **First explicit entry anchor located:** the round-25 draft `ScribePlanned26.md:12,19` calls the due calculation an inference at first, then states `verified-at + cadence`; it gives 2026-10-19 + 90d = 2027-01-17 and classifies `on-release` as unscheduled, not overdue. This is subsequent design, not a recovered r24 decision.
- **`on-release`:** r24 admitted it as a token; usage points to a source-revision trigger: `knowledge/claim-support-states-r24.md:3-5` says to re-open the cited sections. Round-25’s explicit interpretation is event-triggered with no calendar deadline (`ReviewSourcesRecheck.md:3,19-20`). So it is not a dated interval; the r24 criterion itself did not specify event detection/monitoring.
- **Claim 2 comparison:** `corpus/evidence/round26-claims.md:65-73` now makes the added choices explicit: absolute ISO date is the due date; `Nd` is added to valid `verified-at`; `on-release` is `freshness=event`; dated entries are overdue only when `as-of` is strictly later than due. The `verified-at` anchor follows the r25 draft, and the event classification fits the later event-trigger interpretation. None contradicts a formula or trigger rule recorded in r24: those semantics were absent there. They are new operational choices, not evidence of what r24 had already specified.
- **Limit:** “current”/“overdue” classifies the declared schedule only; it does not establish that the source was reopened or the entry’s claim is true (cf. `QUALITY.md:28-31`).

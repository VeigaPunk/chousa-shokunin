# ScribeKnowledge — parser repairs vs. semantic verification

**Assigned axes:** C1 operability, C2 freshness, C3 calibration. **Provenance:** local source reads only; no commands, gate runs, fixture generation, tool installs, or production edits. This is static analysis, not execution evidence.

## Findings

- **C1 / operability is a harness gate, not claim evidence.** The round27 contract requires usage-error controls and counts verdict records using an anchored `^RESEARCH_GATE: ` (corpus/evidence/round27-claims.md:5–7). The helper at tools/research-gate.sh:5983–6008 uses that anchored count and distinguishes expected exit-2 from one verdict; the accepted r26 failure remains ground truth, not a rerun. Suggested acceptance: retain every original case and require the independent controls specified by the claim. This says nothing about claim truth.
- **C2 / freshness is date parsing and arithmetic.** The contract specifies ASCII dates, leading-zero and all-zero cadence controls, bounded year/date arithmetic, strict overdue comparison, and unchanged plain mode (corpus/evidence/round27-claims.md:9–11; corpus/evidence/round26-claims.md:52–82). Relevant implementation is `metadata_iso_date` / `metadata_add_days` at tools/research-gate.sh:2295–2358, with CLI validation at :6295–6297. Expected repair is locale-independent ASCII grammar and terminating decimal normalization while retaining the stated calendar semantics. Passing those synthetic/differential controls would establish only this freshness behavior.
- **C3 / calibration is registry parsing and metadata linkage.** The requested fresh-header, width, token-identity, and filesystem-path requirements are in corpus/evidence/round27-claims.md:13–15; the registry semantics and required defect adjudication are in corpus/evidence/round26-claims.md:84–116. Parser surfaces: tools/research-gate.sh:2361–2469 and source-ID scan at :2472–2506. Path handling warrants separation: `ptr_file_part` strips at the first colon (:573–575), and `is_denylist_path` invokes it (:595–606), including checks on canonical paths (:621–637; registry checks :2374–2383). Keep citation-anchor splitting for pointer resolution, but apply denylist checks to complete filesystem paths. Expected controls are the synthetic cases specified in round27, without relaxing existing pointer/used-by rules.
- **Semantic claim verification remains a different question.** `verify_claims` reads a bounded local source and checks whether a declared span is present (and, for contradicted expectations, whether its marker occurs in the span lines); see tools/research-gate.sh:1315–1459. That is not an adjudication that a public-source claim is true. The round27 source says “fixing these regressions does not retroactively admit r26 or claim full criterion6 semantic verification” (corpus/evidence/round27-claims.md:19). Registry parser repairs therefore must not be reported as criterion-6 semantic verification.

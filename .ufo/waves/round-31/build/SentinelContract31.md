Reviewed frozen `corpus/evidence/round31/claims.md` and the then-read `tools/research-gate.sh` implementation sections below. ## Findings

1. **High — optional-field type/presence ambiguity can bypass binding.** Evidence: `tools/research-gate.sh:1059-1069` (`json_str` recognizes only quoted strings; `jfield` maps no match to empty), `:1367-1371`; contract `claims.md:23-25,74-76`. If C1/C2 reuse `jfield` without separately detecting the key and JSON type, a present non-string such as `"line":8` or `"sha256":null` looks absent. A claim can then get the legacy unbound verdict instead of required `invalid`. A regex over the full line also does not establish that a key is unique/top-level. **Smallest remediation:** distinguish absent from present; parse these as unique top-level JSON string fields, reject present non-strings and duplicates (and malformed JSON) as `CLAIM_RECORD_INVALID`.

2. **High — untrusted `line` can become arithmetic/sed code.** Evidence: contract `claims.md:23-31`; existing line extraction/arithmetic and sed use `tools/research-gate.sh:1118-1124,1295-1320,1416`. If raw `line`/range text is interpolated into `(( ))` or a sed address/script, malformed operators/commands can change evaluation; a sed-script injection can execute commands. Even digit-shaped input is unsafe to use directly as Bash octal arithmetic: `08` errors, and very long valid decimals overflow/wrap. The contract specifically treats a syntactically valid line beyond EOF as a mismatch, not invalid (`claims.md:24,39-42`). **Smallest remediation:** validate exact decimal grammar first (`N>=1`, no zero prefix; `M>N`), never evaluate the string or use it as a sed program/address; compare validated decimal strings (length then lexical order) or safely convert only bounded source-derived values. Invalid values must never reach arithmetic or sed. Check any boundary-delimited occurrence against the named range, not just the first occurrence (`claims.md:27-31`; existing `tok_span_at` returns first at `:1310-1320`).

3. **High — hashing before the refusal/cap chokepoint breaks the read boundary.** Evidence: `claims.md:77-82`; `tools/research-gate.sh:1135-1238`, especially raw/canonical denylist and resolution (`:1139-1195`) and ordered `nlink → size → device` probes (`:1197-1235`). Hashing the claim's path before `claim_source_path` lets a claim trigger reads/hashes of denied, out-of-root, multi-linked, cross-device, or oversized content; hashing an oversized file first defeats the 8 MiB pre-read cap. **Smallest remediation:** resolve/refuse first; only hash after successful helper return, preserve the helper's symlink canonicalization and refusal order (hardlink before size, size before device), and never hash a refused source. Hash the exact original bytes (including CRLF/final newline), not normalized text or a `$(cat)` result (`claims.md:84-90,133-134`).

4. **Low — separate hash/read opens admit a revision/span TOCTOU.** Evidence: hash contract `claims.md:77-80`; current source is read later via `cat` at `tools/research-gate.sh:1401-1405`; frozen exclusions explicitly include “races between hashing and reading a file that changes during the run” (`claims.md:144-145`). With concurrent write/replace access, hash can attest bytes A while span verdict checks bytes B. This is an explicit scope limitation, not a frozen-counter failure. **Smallest remediation if race resistance is desired:** hash and match one opened, size-bounded snapshot/descriptor; otherwise retain and state the documented limitation, and do not claim the hash pins the bytes actually searched under concurrent mutation.

5. **Medium — echoing malformed `sha256`/`line` into findings enables log injection and disclosure.** Evidence: JSON unescaping materializes `\n`, `\r`, and other escapes at `tools/research-gate.sh:1071-1108`; `emit_finding` appends/prints its observation without escaping at `:392-395,1467-1470`; secret scanning reports only path/line/class at `:686-706`. An invalid value containing escaped newlines or terminal controls, echoed in a new finding, can forge finding/verdict-looking lines or alter terminals; echoing secret-shaped malformed values or source/span data can disclose content. **Smallest remediation:** use fixed observation tokens for invalid/mismatch findings; never include raw hash, line, span, source bytes, or context in FINDING text. If a correlation value is necessary, use an allowlisted, length-bounded safe identifier and keep content out of logs.

## L1 implementation constraints

- Parse field presence/type independently; only absent is legacy behavior. Reject malformed present fields before any field-driven computation; reject duplicate/ambiguous field definitions.
- C1: enforce decimal grammar without arithmetic/eval/sed on attacker input; valid huge line numbers remain syntactically valid and simply fail to bind. Search for any matching occurrence on the requested line/range.
- C2: after source refusal checks pass, compare the lowercase 64-hex value against SHA-256 of exact source bytes; stale wins over span outcome; no hash/read on a refused source. Keep the existing canonical path and hardlink/size/device precedence.
- Keep all new FINDING observations content-free and single-line; do not print hash values or source/span text. Separate-open races are explicitly unclaimed by v1 unless the implementation deliberately snapshots bytes.

### Enforcement gaps and minimum corrections

1. **Revision/role binding is not self-contained.** K:396–404 stores counter hash, gate path/hash, seed, UTC, return code, and scores, but no lane commit or run role. A gate path is not a revision. Several lane revisions can share identical gate bytes. The frozen design revision itself shares the base gate bytes (C:3–4; evidence command 4), while deliberately containing a failing base-control receipt. **Correction:** a committed companion record must associate each receipt's content hash with its immutable tested lane revision, gate hash, counter hash, and control/feasibility/candidate role. Do not infer candidate status from a true boolean or receipt filename.
2. **No lower run can be proven absent from receipts alone.** `--receipt` is optional (K:326); K:392 prints the count before attempting the receipt write (K:395–410). [INFERENCE] A run can print a lower count and leave no receipt, including when the requested receipt cannot be written. **Correction:** the scoring operator must preserve stdout, process exit status, and a per-run ledger for every candidate run, including unsuccessful receipt writes. This is an external completeness obligation, not something the current JSON schema proves.
3. **Tip-only or path-only census can lose a committed miss.** K:406 overwrites a receipt path. [INFERENCE] Reusing a path and committing a later passing receipt can hide an earlier committed miss from a final-tree-only tally, although Git history still retains the earlier blob. **Correction:** immutable per-run paths plus a census of all receipt versions committed during the round, not just files present at the final tip. Include the actual census command and selection rule; round-32 D2 explicitly requires a counting command (`corpus/lessons/round-32-verifier-spotcheck.md:159–162`).
4. **Freshness and all-runs aggregation are procedural.** K:325,329 accepts any seed and K:390 checks only this run. **Correction:** the committed aggregation must demonstrate two fresh, distinct seeds for the same tested identity and list every attributable miss. It cannot choose two passes and drop a third failure. Keep controls separate from candidate evidence without erasing their recorded results.

**Finding:** the kill rule is enforceable over the complete set of correctly attributed committed receipts; it is not fully enforceable from an isolated receipt, a final-tip count, or the per-run boolean. The stronger no-run wording additionally needs complete external run capture. This is a provenance/aggregation defect to repair outside the frozen counter, not permission to amend the rule after scoring. This section concerns the scoring kill rule, not host process signalling.

## 6. Falsify-wave recommendation and minimum safe disposition

1. **First distinguish measurement from implementation:** exact rc/rollup/required-invalid-finding controls (section 3). These can violate the written contract on the existing fixture while keeping every counted observation. A proven 144/144 control follows C:74–75's pre-data route; do not redefine success around it.
2. **Then target the actual reader:** duplicate id/span/expect/marker; duplicate non-string/multiple occurrences; nested-only required fields; nested duplicates; top-level non-string line/sha; compact/tab formatting; empty and boolean/null subtrees; simultaneous line+sha; read-value escape parity and decoding. These are in-scope operability obligations, not merely optional robustness.
3. **Run inherited behavior as no-harm, not as a changed denominator:** R31 range/repeated/multiline/invalid classes, revision-pin cases, contradiction markers, framing, source refusals and output/exit checks. Keep the frozen counter intact. The new reader should not make a second authority or silently alter raw-vs-decoded string identity.
4. **Keep the excluded families clearly labelled.** `marker_default`, malformed JSON, escaped key spellings, unread duplicates, other modes, and semantic truth are not grounds to claim the frozen counter measured more than it did. Scope expansion or design revision belongs to the canonical process, not this critic.
5. **Make global P1 auditable externally:** immutable revision-bound receipt/run records, two fresh seeds, full committed-history census with its counting command, and every lower attributable run retained. A local true label is never the aggregate result.

The duplicate-key omissions, decoded-value identity risks, malformed/non-string handling, and exact-output/exit holes are fixable defects if present in an implementation. Finite topology/string sampling and the explicit exclusions are measurement-scope limits: they cannot support universal coverage by saturation. This report does not substitute a critic's judgment for the canonical judge.

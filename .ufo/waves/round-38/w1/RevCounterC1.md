## Findings
1. **High (calibration) — `base_env()` leaves caller startup channels live; the counter cannot tell "pin works" from "interposer never fired".** `c1-count.py:94-101` scrubs only `BASH_FUNC_`, `CHOUSA_`, `RESEARCH_GATE_`; `BASH_ENV`, `PATH`, `TMPDIR` pass through, and `subprocess.run(["bash", gate, …])` resolves `bash` via caller PATH (`:104-105`, `:111-112`). Evidence 4/5: the committed 2/7 control scores 7/7 under one caller variable, and a gate with no env pin scores 7/7 when `bash` does not import functions. `hold-fn-benign` (`:70`, `:138`) has no observable and is no canary; the only proof the channel is live is the r37 baseline itself. The receipt (`:242-262`) binds seed/counter/expect/gate hashes but no runtime identity (bash version, import policy, PATH), so a rerun on another host is unverifiable. Fix direction: scrub/record `BASH_ENV`+`ENV`+`PATH`+`TMPDIR` into the receipt, and add a positive control (assert `declare -F env` inside the pinned child, or an in-counter deliberately-vulnerable control gate).
2. **High (calibration) — drift cells never exercise the hostile env, so drift-mode pinning is untested.** `denv = base_env()` (`:174-175`) strips the scenario function before `--drift`. Evidence 6: a gate that pins only `--pin` still prints 7/7, while its `--drift` is demonstrably interposable (`+GATE_GREP`, rc 2 under suppress). The clean drift env *is* the right control for the phantom (`-GATE_GREP` comes from the poisoned baseline; a hostile drift env would run against the foreign root too and mask the cell), so this is a coverage hole, not a wrong control: add a hostile-drift cell rather than replace the clean one.
3. **Medium (calibration) — the refusal observable is a token-anywhere test, not the named refusal.** `:178-181` tests `"ENV_PROVENANCE" in (proc.stderr + proc.stdout)` (streams concatenated without separator, no reason/location check). Evidence 7: r37 contains zero override code, yet both override cells pass when the caller prelude forges the token; conversely a refusal for a different ENV_PROVENANCE reason (bad override vs. unassignable pin variable) is indistinguishable. Fix direction: match the full `research-gate: ENV_PROVENANCE refused: <reason>` line on stderr and assert the expected reason per scenario.
4. **Low (operability) — no child timeout.** `subprocess.run` at `:104-105` and `:111-112` sets no `timeout=`; a regressed capture blocks the counter forever instead of refusing exit 2 (the gate bounds its own env probe with `/usr/bin/timeout 10`, `research-gate.sh:485-487`). `grep -n timeout c1-count.py` → NONE.
5. **Low (fixture robustness) — `FN_ROOT` interpolates a path into shell source.** `:67-69` builds `CHOUSA_ROOT="%s"`; `:144-146` interpolates `work` (derived from `C1_TMP` at `:218`). A `C1_TMP` containing `"`, `$` or a backtick changes the injected root silently. Default use unaffected.
6. **Info (fidelity PASS) — raw `BASH_FUNC_env%%` delivery.** Byte form differs from a real `export -f` (real bash normalises to `() {  …\n}`, counter ships one line), but the importer accepts it, it executes, and it re-exports to grandchildren (evidence 3). Fixtures cover re-add (echo/root) and suppress; the "drop the `-u` scrubs, forward everything else" variant is subsumed by suppress for the capture-fails cell.
7. **Info — anchors are correct.** `count_echo_lines` matches `startswith("GATE_GREP: ")` (`:126`), column-0 anchored with the space, against the gate's production stderr line (`research-gate.sh:417-418`) merged into `capture.txt` (`:4004`); missing file returns -1 (`:121-122`), distinct from 0. `drift_line` keeps the LAST stdout `GATE_DRIFT:`-prefixed line (`:114-116`); the gate prints exactly one (`:4221`), and the expectation compares the full string, so `GATE_DRIFT:none` would fail. Scenario env additions are minimal (`:138/140/142/146/149/155`), and scrubbing `CHOUSA_*`/`RESEARCH_GATE_*`/`BASH_FUNC_*` (`:98-100`) keeps the caller from leaking the scenario intent directly.

## Limits
- Landed 7/7 and r37 2/7 are genuine on this host; the findings attack the counter's separation strength, not this run's arithmetic.
- Not tested: `LD_PRELOAD`/loader (named C1 limit), `SHELLOPTS=noexec` (named limit), `LC_*`/`SHELLOPTS` beyond import behaviour, `--selftest` bare-`env` paths, `c2-count.py`/`verify-receipts.py` (C2 lane).
- The PATH shim `bash -p` is synthetic caller control; it demonstrates sensitivity, not a default-host result. `bash -p` also skips `BASH_ENV`, so evidence 5 isolates import policy.
- Interposition *inside* the capture child (verify-all) was checked only by grep (no bare `env` outside `--selftest`); not exercised dynamically.

## Findings
1. **c2 receipt field `subject_counter` (c2-count.py:303) is dead.** Written into 3 committed receipts, never read by any scenario or by verify (read set above); strip+re-seal proves the verifier path indifferent. Deleting it shrinks the claim surface: it is provenance by convention — unlike `counter_sha256` it binds no digest, so it adds a doctorable-but-digest-masked field without adding verifiable identity. Tradeoff: receipts lose the human pointer to which counter the scenarios drove (the base receipt uses it to show the r37 counter). The alternative — binding it (`subject_counter_sha256`) — is an addition, L1's call. Note the c1/c2 asymmetry it introduces.
2. **c2's own `--tmp` option is dead to code.** No caller passes it (evidence above); the documented human channel is the `C2_TMP` env fallback, which is what this seat's runs used. Deleting shrinks the CLI by one duplicate channel; the env fallback and `tempfile.gettempdir()` remain. c1's `--tmp` MUST stay — it is live (c2's fixtures hardcode `--tmp work` into every subject-counter invocation, and the r37 counter accepts it).
3. **Receipt path fields `gate`, `counter`, `expectations` are dead to code** (both writers). Verify takes gate/counter/expectations identity from its CLI args + the sha fields; the path fields are never read (strip-proven on c1). Deleting them from the two writers shrinks the digest-bound surface and breaks nothing: the fields are not in REQUIRED, so committed receipts still verify. Tradeoff: a receipt alone no longer names what it scored (seed + shas still identify the bytes). Explicitly NOT `gate_sha256` (the alias): load-bearing (control run) and named by the frozen C1 kill rule — but note it duplicates `gate_sha256_pre` (two authorities, one fact); unaliasing needs a claims erratum, not a silent edit. `seed` also verifies-unread but is claim-named ("two fresh seeds") — keep.
4. **`predicate` string field — dead on frozen bytes, LOAD-BEARING under the integration.** On 504c1d2 it is written by both counters and read by nothing (verify re-derives `predicate_holds`; strip-proven). But the live integrated verifier puts `predicate` in REQUIRED (verify-receipts.py:67 live) and family-checks it against the counter basename's frozen string via `FAMILIES` (:60-63, :135-140, `predicate-mismatch`), so stripping it there fails every receipt `missing-field predicate`. Round-39 disposition: drop this candidate or re-scope it as frozen-bytes-only; candidates 1 and 3 remain safe live (the live verifier still never reads `subject_counter`, `receipt["gate"]`, `receipt["counter"]`, `receipt["expectations"]`).
5. **c1 `setup_scenario`'s second return value `foreign` is dead plumbing.** Sole write `foreign["root"]` (c1-count.py:147), sole consumer discards it (`additions, _foreign = …`, c1-count.py:163). Deleting the dict return is behavior-neutral — keep the `os.makedirs` (the FN_ROOT fixture should point at a real dir). Shrink: one dead return-channel.

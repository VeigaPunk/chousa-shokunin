1. **HIGH — the claim's override-accept half has no measurement (false pass).** `expectations.jsonl` has only two override rows, both negative (`env-override-missing`, `env-override-fake`, c1 rows 6-7); `run_scenario`'s refusal assertion (`c1-count.py:192-195`) checks only the family prefix `research-gate: ENV_PROVENANCE refused:`, never the reason and never a *successful* override. The gate's own selftest covers only the same two negatives (`research-gate.sh:8441,8456`), so nothing in the round's evidence surface distinguishes "verified override" from "override deleted". This is a do-nothing path on half the claim, not just a weak assertion. Fix direction: an eighth cell that pins through a valid absolute GNU env override and requires the same baseline/lines as `hold-plain`.

2. **HIGH — unscrubbed `POSIXLY_CORRECT` moves the verdict (false kill).** `base_env()` (`c1-count.py:104-111`) scrubs the bash startup channels (`BASH_ENV`/`ENV`/`SHELLOPTS`/`BASHOPTS`) but not the GNU-tool behaviour switch the gate's *pinned* binaries consume. GNU grep 3.12 honours `POSIXLY_CORRECT` and stops treating `--` as an end-of-options (evidence 2), so `[[: … -eq 1 ]]` at `tools/research-gate.sh:4008` sees `path:1` and the pin refuses; landed counter prints 2/7. Because the frozen kill rule says "any run against the landed gate below 7/7 kills C1", a runner whose environment exports `POSIXLY_CORRECT` (CI images and `env -i` wrappers do) produces a false kill, and the receipt records nothing about it. `POSIXLY_CORRECT` is the same class as the scrubbed `SHELLOPTS`: bash also enters POSIX mode on it (`bash --version` 5.3.20 here).

3. **MEDIUM — `TMPDIR` is consumed by the gate and unscrubbed.** `base_env()` keeps it, and `gate_canonical_capture` builds its fixture under `${TMPDIR:-/tmp}`; an unwritable/full/missing `TMPDIR` takes the landed run to 2/7 (evidence 3) with `pin_rc=2`/`pin_file=False` that looks exactly like a genuine capture failure. `TMPDIR` is also inherited by the inner capture child. Neither the receipt nor the counter's output records the effective temp base, so the two 7/7 committed receipts cannot prove a sane `TMPDIR` (the r37 Erratum-4 "seed-invariant" class, now an environment-invariance gap).

4. **MEDIUM — the scrub is overbroad on the gate's documented escape hatches.** `base_env()` deletes every `CHOUSA_*` and `RESEARCH_GATE_*` key (`c1-count.py:105-108`) with no re-injection flag, so an operator cannot supply `RESEARCH_GATE_ENV`/`RESEARCH_GATE_GREP` even when the host lacks `/usr/bin/{env,grep}` — the exact case the gate's own refusal messages point at ("set RESEARCH_GATE_ENV to an absolute path").

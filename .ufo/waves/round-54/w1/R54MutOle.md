## 3. What the seven survivors break (each with a concrete input)

These are **coverage findings about the counter**, not proposals to change the frozen
predicate. Each survivor is a real divergence from the pristine tool that the counter's
frozen checks cannot see; the input that would see it is given.

### m05 — `ccpText` ignored: the text form leaks the *non-main* stories
The pristine emits CP 0..ccpText (main story only); m05 emits every piece, so header
(`ccpHdd`), text-box (`ccpTxbx`) and other story text is appended. The leak is real on
the pinned captures but small, so the 0.90-1.10 length band swallows it:

```
54fe0734c01f699e735b4b0a pristine_ratio=0.9719 m05_ratio=0.9786 extra_ws0=79  extra='GB/T 30279—XXXX\n\nII\n\n…'
b539a80218080da56a75b624 pristine_ratio=0.9900 m05_ratio=1.0537 extra_ws0=51  extra='限定是否第一作者\n\n限定文章发表时间\n\n…'
bdff491a75c6abeda1d9c01d pristine_ratio=0.9989 m05_ratio=1.0014 extra_ws0=32  extra='—— 4 —\n\n\n— 3 ——\n…'
```
**Kill input (verified through the counter's own `leg_real`, unmodified):** the pinned
capture `b539a80218080da56a75b624` with its FIB `ccpText` field (file offset 588) set
from 889 to 444 — the piece table is untouched, only the story boundary moves:

```
$ python3 analyze9.py     # imports c1-count.py and calls c1.leg_real(c) directly
pristine-capture-text        leg_real -> PASS  1 captures
m05-ccptext-ignored          leg_real -> FAIL  b539a80218080da56a75b624 length ratio 2.151
```
A generator change that would also kill it: a `.doc` with a large *footnote* story (the
GEN leg only makes documents with empty stories beyond `ccpText`).

### m06 / m07 — `0x07` / `0x0D` emit nothing: the whitespace-free form is unchanged
Both drop a newline, so `ws0(text)` is byte-identical to the pristine's, and the
counter's REAL leg compares **whitespace-free** forms only. The line structure differs
massively, and a line-exact oracle separates them (oracle_lines / tool_lines /
oracle_lines_missing_verbatim, pristine vs m06 vs m07):

```
54fe0734c01f699e735b4b0a  oracle_lines=344
    pristine     ws0=11448 tool_lines=1377 missing_verbatim=202
    m06          ws0=11448 tool_lines= 354 missing_verbatim=202
    m07          ws0=11448 tool_lines=1043 missing_verbatim=344
b539a80218080da56a75b624  oracle_lines=14
    pristine     ws0= 792 tool_lines=  47 missing_verbatim=  1
    m07          ws0= 792 tool_lines=   0 missing_verbatim= 14
```
On a generated document a per-line item assertion is decisive — 7/7 items for the
pristine, 2/7 for m06, 4/7 for m07:

```
pristine   stdout='alpha paragraph one\nbeta paragraph two\ncellA\ncellB\n\ncellC\ncellD\n\ngamma paragraph three\n'
m06        stdout='alpha paragraph one\nbeta paragraph two\ncellAcellBcellCcellDgamma paragraph three\n'
m07        stdout='alpha paragraph onebeta paragraph twocellA\ncellB\n\ncellC\ncellD\n\ngamma paragraph three'
```
**Kill input:** a `.doc` with a table (the GEN documents have one) plus a per-line item
assertion instead of the whitespace-free one; the GEN leg also uses `ws0`.

### m09 — `fObfuscated` not checked: the ENCRYPTED leg never sets it alone
`c1-count.py:218` sets `b[o + 0x0B] |= 0x01` (fEncrypted) or `0x81` (fEncrypted **and**
fObfuscated) — never fObfuscated alone, so the mutant's gap is untested. A FIB patched
so that only fObfuscated is set separates them:

```
m09-obfuscated-only pristine  rc=2 err='REFUSED ole-encrypted: FIB fEncrypted/fObfuscated set'
m09-obfuscated-only m09       rc=0 stdout=b'alpha paragraph one\nbeta paragraph two\ncellA\ncellB\n\ncellC\ncellD\n\ngamma paragraph…'
```
**Kill input:** the ENCRYPTED generator patched to `b[o+0x0B] |= 0x80` (fObfuscated
without fEncrypted) — the pristine refuses, m09 emits the text.

### m12 — chain loop detection removed: no cycle is ever generated
The counter's MALFORMED leg cuts the file short or sets a sector shift of 7
(`c1-count.py:233,236`); neither creates a cyclic FAT chain. A self-referential FAT
entry does, and the mutant then **hangs** (the pristine refuses immediately):

```
m12-dir-loop pristine  rc=2 err='REFUSED ole-malformed: sector chain at 16'
m12-dir-loop m12       rc=TIMEOUT (15 s cap; the pristine never loops)
```
**Kill input:** a generated `.doc` whose FAT entry 0 points at itself — the pristine
refuses `ole-malformed`, m12 spins until the tool timeout.

### m13 — `nFib` check removed: no pre-Word-97 document is ever generated
The counter's NONWORD leg uses a spreadsheet, which has no `WordDocument` stream at all,
so the `nFib >= 0xC1` branch is never reached. A FIB with `nFib = 0x0060` separates them:

```
m13-old-nfib pristine  rc=2 err='REFUSED ole-not-word: nFib 0x60 predates Word 97'
m13-old-nfib m13       rc=0 stdout=b'alpha paragraph one\nbeta paragraph two\ncellA\ncellB\n\ncellC\ncellD\n\ngamma paragraph…'
```
**Kill input:** a generated Word 6/95 `.doc` (`nFib < 0xC1`) — the pristine refuses
`ole-not-word`, m13 emits the text.

### m14 — U+FFFD silently replaced by `?`: a laundering mutant
The counter's GEN/REAL legs ban U+FFFD in the text form, so m14 passes by construction;
but m14 is byte-identical to the pristine on every input the counter accepts (**5/5
pinned captures, identical stdout**), so it is an *equivalent* mutant for this corpus.
The divergence appears only on a document with an invalid UTF-16 piece, where the
mutant launders the error the counter looks for:

```
m14-lone-surrogate pristine  rc=0 U+FFFD=1 stdout=b'alph\ufffd paragraph one\nbeta paragraph two\n…'
m14-lone-surrogate m14       rc=0 U+FFFD=0 stdout=b'alph? paragraph one\nbeta paragraph two\n…'
```
**Kill input:** a document with an unpaired UTF-16 surrogate in a piece (patched into
the piece's bytes) — the counter's U+FFFD rule then passes for m14 and the error is
hidden. No pinned capture has invalid UTF-16 (`U+FFFD in pristine outputs: 0`).

## 4. Coverage summary for the lane

The counter's discriminating power is real but uneven: it kills 9/16 single-point
mutants (the field rule, compressed-piece decoding and `fc` halving, fEncrypted,
`fWhichTblStm`, the mini-stream cutoff, the partial final sector, magic-based OLE
detection). The seven survivors cluster into three blind spots, each with a concrete
input above: (a) **story boundaries** — the whitespace-free comparison cannot see a
different *shape* of text form (m05, m06, m07); (b) **refusal branches never generated**
— fObfuscated alone (m09), a cyclic FAT chain (m12), a pre-Word-97 FIB (m13);
(c) **a laundering mutant** on a corpus with no invalid UTF-16 (m14). m05/m09 are the
cheapest to fold into the generator; m06/m07 need a line-exact oracle. All seven
survivors were re-run **unseeded** and still report `LEGS=6/6`, `C1=PASS`.

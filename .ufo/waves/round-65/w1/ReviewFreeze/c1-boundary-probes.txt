# BOUNDARY OBSERVATION (not a defect against the frozen claim):
probe.crlf         rc=0 RECEIPT_PIN=PASS
  # A receipt with CRLF (\r\n) line endings PASSES the reference validator.
  # Cause: str.splitlines() normalizes \r\n, so the header equality and empty-separator
  # checks never see the \r. The byte-level format stated in the claims ("empty separator",
  # ordered headers) is therefore line-ending-tolerant in the reference implementation.
  # None of the 20 frozen cases pins byte-exact line endings; the frozen counter inherits
  # this tolerance. Receipt bytes are not themselves digest-bound (the digest binds the
  # named blob), so CRLF does not weaken blob binding; it is an interface-tolerance note.

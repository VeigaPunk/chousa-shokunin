## 3. Behaviours not pinned by the contract text (named deliverable)

Contract text attacked: claims.md C1 format sentence + "0 consistent,1 invalid,2 usage/environment"; tool docstring `tools/receipt-pin.py:13-14`.

1. **"2 usage/environment" is only half-true (strongest defect).** Docstring (receipt-pin.py:13-14) and claims.md assign exit 2 to "usage/environment". Landed bytes only produce 2 for argparse usage errors (`p.error`, lines 34–35, missing args). Environment failures are swallowed by `except (OSError, UnicodeError, ValueError)` (line 54) and exit 1. Probe output: `missing-file|rc=1|out="RECEIPT_PIN=FAIL [Errno 2] No such file or directory: '…/probes-out/nope.txt'"` vs `bad-revision|rc=2|err="receipt-pin.py: error: --revision requires …"`. The claim's own 20 cases never exercise a 2-path, so the C1 score is unaffected — but as written, the contract sentence overpromises relative to landed behaviour. Smallest safe correction: contract/docstring should read "2 usage" (argparse) or route OSError to 2; a counter change is neither needed nor permitted post-freeze.
2. **"Exact token" is exact only for PASS.** Frozen ok-clause (c1-count.py:18) checks fail cases by `startswith('RECEIPT_PIN=FAIL ')` prefix only — the fail message text is unpinned (observed messages differ per guard, e.g. cases 4/7/11/18/19 all share the len<5 message though their defects differ). Claim wording "exact exit and token" is stricter than predicate mechanics. Frozen; report as wording gap, not a miss.
3. **EXIT field is unverifiable-by-design, pinned only by disclaimer.** Cases 2–3 (EXIT=1, EXIT=255) PASS with no executed child. Mechanically consistent with claims.md's "header consistency … not execution authenticity" and docstring lines 10–12 — pinned, but only by the disclaimer; the predicate cannot distinguish a truthful nonzero exit from a fabricated one.
4. **"Nonempty output" vs whitespace body.** Contract says nonempty output; implementation requires `"\n".join(lines[4:]).strip()` nonempty (line 52). Probe `ws-body` (body `"   \n"`) → `rc=1 FAIL receipt body must be nonempty`: bytes-nonempty but whitespace-only bodies are rejected. Contract does not pin this; immaterial to the 20 cases.
5. **"Exactly one of each header, in that order" is positional only.** Enforcement is lines[0..3] fixed positions plus empty separator (lines 40–51); a duplicated header placed inside the *body* would still PASS, and several duplicate-in-header defects fail incidentally via the separator check (case 17 trips lines 50–51, not a dedicated duplicate check). No case tests this; behaviour beyond the positional check is unpinned.
6. **First-error-wins granularity.** Several distinct defects converge on the same message via the len<5 guard (cases 4/7/11/18/19) — verdicts pinned, diagnostics unpinned.
7. **Line endings / trailing newline.** Not pinned by contract. Wave-1 already disclosed CRLF behaviour at lane tip (commit a6b6f93 "L1 boundary probes on the landed validator, CRLF behaviour disclosed"); out of this seat's narrow scope, cited for completeness.

## Finding 2 — landed validator rejects every landed round-65 receipt (format break)

What it attacks: consistency among `tools/receipt-pin.py`, the receipts in `corpus/evidence/round65/controls/`, `corpus/knowledge/receipt-identity-r65.md`, and `corpus/evidence/round65/measurement-summary.json`.

- Documented pinned format (`tools/receipt-pin.py:4-6`): `REVISION=<40 hex>`, `EXIT=<0..255>`, `SHA256=<64 lowercase hex> <repo-relative path>`, one empty separator, nonempty body. Enforced at `tools/receipt-pin.py:44-46` (`DIGEST_RE` at line 25 requires `lines[2]` to be the SHA256 header).
- Byte-exact header of the lane's pinned specimen (`od -c` on clone copy of `corpus/evidence/round65/controls/c1-after.txt`):

```
REVISION=0a85189821322e01db06216b5cb82d2d858c19f0\nEXIT=0\nARGV=["python3","-B","corpus/evidence/round65/c1-count.py","--work","/fast/scratch/hyaku/chousa-r65/L1/tip1"]\n\nCASE valid PASS rc=0\n...
```

  i.e. line 3 is `ARGV=…`, not `SHA256=…`.

- Survey over the pinned tree (clone @ 9672a2e): `grep -rl '^SHA256=' corpus/evidence/round65/` → **(none)**; `grep -rl '^ARGV=' corpus/evidence/round65/` → all 8 receipts: `always-fail.txt`, `always-pass.txt`, `c1-after.txt`, `c1-before.txt`, `c1-positive.txt`, `c1-stubs-after.txt`, `c2-after.txt`, `c2-before.txt` (ARGV at line 3 in each).

- Direct run against the lane's own pinned receipt at its own measured revision:

```
$ python3 "$D/tools/receipt-pin.py" --receipt "$D/corpus/evidence/round65/controls/c1-after.txt" \
    --root "$D" --revision 0a85189821322e01db06216b5cb82d2d858c19f0
RECEIPT_PIN=FAIL SHA256 header must be 64 lowercase hex plus a relative path   (rc=1)
```

- Positive control, same root/revision, synthetic receipt in scratch conforming to the documented format (digest of `0a851898…:corpus/evidence/round65/c1-count.py` = `454286e8…3dae`):

```
$ python3 "$D/tools/receipt-pin.py" --receipt synth-valid.txt --root "$D" --revision 0a85189821322e01db06216b5cb82d2d858c19f0
RECEIPT_PIN=PASS   (rc=0)
```

  Wrong `--revision` control → `RECEIPT_PIN=FAIL REVISION header missing or not the selected revision` (rc=1). The validator itself is functional on its documented format.

**Consequence:** the receipts the lane froze as round-65 evidence (`measurement-summary.json:10` — `"tools/receipt-pin.py": "SEE c1-after.txt REVISION pin; blob pinned at the measured revision"`) cannot be re-validated by the landed pinned tool; each FAILs at the digest-header gate. Either the receipts are not in the pinned format the knowledge doc (`corpus/knowledge/receipt-identity-r65.md`) and the validator docstring declare, or the validator enforces a header the receipts never carried. As landed, the validator's PASS verdict is unreachable for the lane's own evidence.

Observation (not a defect of the pinned state): `controls/l1-boundary-probes.txt` exists in the live lane working tree but is absent from tip 9672a2e (untracked, written post-commit); it was therefore not part of the pinned attack surface.

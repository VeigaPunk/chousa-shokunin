## 4. Coverage boundary of the frozen C1 oracle (the surviving mutants)

The five survivors are, by definition, behaviours the frozen 20-case oracle does **not** pin. Each was probed directly against the mutated and the pristine validator to establish whether it is *live* (acceptance actually widens) or *equivalent* (indistinguishable from pristine):

| Survivor | Direct probe (mutant vs pristine) | Verdict |
|---|---|---|
| **M5** — empty-body guard `:52` | receipt = `REVISION/EXIT/SHA256` + blank separator + whitespace-only body line: **mutant `RECEIPT_PIN=PASS` exit 0**; pristine `RECEIPT_PIN=FAIL receipt body must be nonempty` exit 1 | **live, unpinned** |
| **M7** — canonical path-form `:48` | receipt with path `./SKILL.md` + correct digest: **mutant `RECEIPT_PIN=PASS` exit 0**; pristine `RECEIPT_PIN=FAIL path must be canonical and repository-relative` exit 1 | **live, unpinned** |
| **M8** — blob-existence `:58` | receipt with path `missing-r65.md` + digest of empty bytes `e3b0c442…7852b855`: **mutant `RECEIPT_PIN=PASS` exit 0**; pristine `RECEIPT_PIN=FAIL no blob …:missing-r65.md in --root` exit 1 | **live, unpinned** |
| **M11** — receipt-length guard `:38` | 2-line receipt: pristine `RECEIPT_PIN=FAIL receipt needs four header lines, an empty separator and a body` exit 1; **mutant raises an uncaught `IndexError: list index out of range` at `receipt-pin.py:44` — empty stdout, traceback on stderr, exit 1** | **live, unpinned** (also a robustness defect: a clean FAIL becomes an unhandled exception) |
| **M4** — `..` path guard `:48` | mutant on a `../SKILL.md` receipt: `RECEIPT_PIN=FAIL no blob d6ed8155…:../SKILL.md in --root` exit 1 — the *reason* changed from the validator's own guard to git's refusal: `git -C "$D" cat-file blob "$B:../SKILL.md"` → `fatal: '../SKILL.md' is outside repository at '…/clone'` (exit 128); interior form `corpus/../SKILL.md` → `fatal: path 'corpus/../SKILL.md' exists on disk, but not in 'd6ed8155…'` (exit 128) | **equivalent mutant** — git refuses *every* `..` path in `rev:path` syntax, so no receipt-level case can isolate this guard |

### Why the survivors survive — the masking structure

The 20 frozen cases are built by textual substitution of one valid receipt, and several "negative" cases are **masked by an earlier guard**, so they do not reach the guard they appear to cover:

* `no-body` (`c1-count.py:16`, `v.split('\n\n')[0]+'\n\n'`) produces a **4-line** receipt → rejected by the length guard `:38` before the empty-body guard `:52` is ever evaluated → M5 survives.
* `no-separator` (`v.replace('\n\n','\n')`) likewise yields 4 lines → dies at `:38`; the separator guard `:50` is only reached by the `duplicate` case → M10 was killed by `duplicate` alone.
* `missing-blob` (`v.replace('SKILL.md','missing-r65.md')`) keeps a **non-empty** digest, so once the blob-existence check `:58` is gone the digest comparison `:60` still fails → M8 survives (a receipt carrying the *empty-blob* digest would pass — probed above).
* `traversal` (`v.replace('SKILL.md','../SKILL.md')`) is rejected by git, not by the validator → M4 survives.

**Net boundary statement.** The frozen oracle pins: revision-equality, exit range `0..255`, digest hex-case and digest-vs-blob equality, header order, duplicate-`EXIT` rejection, uppercase-digest rejection. It does **not** pin: the empty-body contract, canonical path form, blob existence, the receipt-length contract, nor the `..` component guard (that one is structurally unpinnable at receipt level, being git-redundant).

## 6. Findings for L1 (no edits made here)

1. **The frozen C1 oracle under-pins the C1 contract.** Four live acceptance-widening mutants (M5 empty body, M7 non-canonical path, M8 nonexistent blob with empty-blob digest, M11 length guard → uncaught `IndexError`) all return `CASES=20/20 C1=PASS`. The oracle would still certify a validator that accepts a whitespace-only body, a `./SKILL.md` path, or a receipt for a blob that does not exist.
2. **Concrete case additions that would close the gap** (for a *new/extended* frozen detector — `c1-count.py` itself is immutable and must not be edited):
   * 5-line receipt, whitespace-only body line → kills M5;
   * receipt with path `./SKILL.md` and the correct digest → kills M7;
   * receipt with path `missing-r65.md` and digest `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855` → kills M8;
   * 2-line receipt → kills M11 and catches the uncaught-`IndexError` robustness defect;
   * 5-line receipt whose separator line is non-empty (e.g. `X`) → kills M10 independently of `duplicate`.
3. **M4 should be recorded as defence-in-depth, not as an oracle gap.** The validator's own `..` check is redundant with git's refusal of every `..` path in `rev:path` syntax; the equivalent-mutant result says the check cannot be isolated by any receipt-level case. If the lane wants it pinned, it needs a unit-level probe of the path predicate, not a receipt case.
4. **No defect in the frozen claim or in the landed validator was found** — the survivors are coverage gaps of the detector, not live violations of the *shipped* validator (pristine rejects all four probes). The claim C1 as frozen remains consistent with the implementation; what the SCORECARD can honestly say is bounded by the oracle's coverage as enumerated in §4.

### F1 (medium, in-scope interface deviation, outside frozen-counter coverage) — environment failures exit 1, never 2

- **What it attacks:** tools/receipt-pin.py:54-64 vs contract sentence **"0 consistent,1 invalid,2 usage/environment."**
- The only exit-2 path in the file is argparse usage errors (line 35 `p.error` on a malformed `--revision`; missing required args likewise argparse→2 — verified: `--revision deadbeef` → `receipt-pin.py: error: --revision requires a full lowercase 40-hex object id`, exit=2). All *environment* failures are funneled into the `except (OSError, UnicodeError, ValueError)` handler at line 62 and return 1:
  - `git` binary absent: `RECEIPT_PIN=FAIL [Errno 2] No such file or directory: 'git'` exit=1 (probe: `PATH=<scratch>/pbin` containing only a python3 symlink, valid receipt, valid root). `FileNotFoundError` is an `OSError`, caught at line 62.
  - `--root` not a Git repository (receipt itself fully valid): `RECEIPT_PIN=FAIL no blob <rev>:blob.txt in --root` exit=1 (probe: valid receipt, `--root` an empty non-git dir). A returncode!=0 from `git cat-file` (line 58) is treated as receipt invalidity, indistinguishable from a genuinely missing blob.
  - Receipt path unreadable/missing: `RECEIPT_PIN=FAIL [Errno 2] No such file or directory: '...missing.txt'` exit=1.
- **Contract sentence violated:** "…2 usage/environment" — the implementation never emits 2 for environment faults.
- **Scope determination:** inside the claim's stated interface scope (exit-code contract is interface, and the claims.md scope note "interface/consistency coverage, not … general parser safety" does not carve out exit-code semantics), **but** outside frozen-counter coverage: none of the 20 frozen cases (c1-count.py line 16) exercises a broken environment — all run with a healthy lane repo and existing receipt files. Cannot flip R65-C1 as frozen; the L1 should weigh whether "usage/environment" was intended to be counter-enforced.

### F3 (observation, no violation under canonical reading) — EXIT accepts only canonical decimal numerals

- **What it attacks:** tools/receipt-pin.py:24 (`EXIT_RE = re.compile(r"EXIT=(?:0|[1-9][0-9]{0,2})")`) + line 42 range check, vs contract sentence **"EXIT decimal 0..255"**.
- Rejected by probes: `EXIT=00`, `EXIT=0255`, `EXIT=+1` → all `RECEIPT_PIN=FAIL EXIT header must be the reported child exit, decimal 0..255` exit=1. Accepted: `EXIT=0`, `EXIT=1`, `EXIT=255`; `EXIT=256` rejected via the `int(...) > 255` guard (regex alone would admit up to 999).
- **Scope determination:** the frozen counter only exercises `0/1/255/256/-1/PASS`; leading-zero and signed forms are unpinned by the contract. Canonical-decimal rejection is the defensible reading; reported as an unguarded ambiguity, not a deviation.

## Contract clauses verified as correctly enforced (line-by-line pass, no deviation)

- **"exactly ordered REVISION full lowercase 40 hex"** — lines 23, 34-35, 40: `--revision` pre-validated with `fullmatch`; receipt line 0 must be exactly `"REVISION=" + a.revision`, enforcing order, uniqueness, full length, lowercase, and equality in one comparison. - **"SHA256 full lowercase 64 hex plus canonical relative POSIX path"** — lines 25, 44-49: `fullmatch` on `SHA256=([0-9a-f]{64}) (.+)`; canonicality via `PurePosixPath` — rejects absolute (`/SKILL.md`), `..` parts (`sub/../blob.txt` probed → FAIL), and any form pathlib normalizes (`sub/./inner.txt`, `./a`, `a//b`, `a/`, `.` → all caught by `str(rel) != m.group(2)` or empty parts; verified against Python 3 pathlib semantics directly). Frozen `traversal`/`absolute`/`short-digest`/`upper-digest`/`wrong-digest` fail exit 1.
- **"empty separator"** — line 50: `lines[3] != ""` → FAIL. Frozen `duplicate` (re-header before separator) and `no-separator` fail exit 1.
- **"Digest binds the Git blob at the declared revision"** — lines 54-61: sole hash input is `blob.stdout` of `git -C ROOT cat-file blob REVISION:PATH`; byte-exact `hashlib.sha256(...).hexdigest()` comparison. Frozen `missing-blob` fails exit 1.
- **"revision must equal caller-supplied --revision"** — line 40 exact-string equality; inherits the line 34 lowercase-40-hex validation.
- **"No working-tree hashing"** — no code path reads the work tree for the hashed object; only `cat-file` output is hashed (lines 54-61).

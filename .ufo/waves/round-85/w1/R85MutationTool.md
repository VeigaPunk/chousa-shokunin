## 4. Survivors — the important finding

Six mutants pass the frozen counter at 354/354. Each is a real behavioural defect with a constructed or
committed-bytes witness; the counter simply never presents the input that separates it from the landing tool.
Witness runner: `scripts/witnesses.py`; records and outputs: `receipts/witnesses/` (summary in
`receipts/witnesses/summary.txt`). "Landing" = the pinned landing tool run on the same record/root.

### S1 — M13 `refetch-key-conjunct-dropped` (sha `11e8d6ab…`)
Dropped `r[2] == key` from the admit REFETCH `any()`: a refetch row is accepted even when its key cell is not
`sha256(url)[:24]`.
Witness: doctored scratch root (`tree-doc-m13`, a copy of the pristine tree; S008's 200 row key cell replaced by 24
zeros), record `receipts/witnesses/W-M13-refetch-key-zero.md`:
- landing: `GATE_RECORD …/W-M13-refetch-key-zero.md:1 S008 FAIL REFETCH`, `GATE_RECORDS files=1 records=1 ok=0 fail=1`, rc **1**;
- M13: same record `… S008 OK`, rc **0**.

Why blind: no committed refetch row has a key that disagrees with `sha256(url)[:24]` (the only mismatch is the TSV
header), and the fresh builder computes the key from the URL, so the conjunct is unobservable from frozen bytes.
Round-86 class to add: **refetch-key-mismatch** — an admit forged from a fixture/doctored row whose key cell is
wrong, expecting `REFETCH`; if the round refuses fixture rows, record the conjunct as unobservable-from-frozen-bytes
and do not claim it is load-borne.

### S2 — M14 `refetch-txtsha-conjunct-dropped` (sha `e2a7b2aa…`)

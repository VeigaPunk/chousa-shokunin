## Schema

Identical to claims-r2.jsonl: one JSON object per line with `id`, `claim`,
`source`, `span`, `expect` (+ `marker` only on `contradicted` entries).
`span` is a byte-exact slice of the cited source (the file was generated by
slicing the pinned archive bytes between anchors, not by re-typing them), so
typographic bytes (`職人気質`, `年季明け`, `一人前`, `—`, `’`) are the source's
own.

## Pre-registered verdict semantics (unchanged)

- `supported` — span occurs as a byte-exact, token-boundary-delimited
  substring of the source; no marker.
- `contradicted` — span occurs and contains the entry's literal `marker`; the
  claim asserts the opposite of what the span says. STRUCTURAL verdict only.
- `unsupported` — the byte-exact quoted probe does NOT occur; a negative
  control, not an adjudication of the topic.

Exact expected counts — `claims=10 supported=7 contradicted=2 unsupported=1
mismatched=0`, `VERDICT_BEARING_CLAIMS=10/10`, `RESEARCH_GATE: CLEAN`,
exit 0. A summary that disagrees means gate drift.
